# SFA Demo — Sales Force Automation

A working prototype covering all 8 demo scenarios from the RFP: customer visits (geo-fenced),
purchase decline alerts, cross-sell recommendations, stock/alternative products, special
pricing approvals, order flow to Sage X3 (simulated), a manager dashboard, and document
sharing via email.

## Stack
Next.js 15 (App Router) + TypeScript + Tailwind + Supabase (Postgres, Auth, Realtime) + Resend (email).
Mobile-optimized PWA for the sales-rep views, desktop dashboard for managers.

## 1. Set up Supabase
1. Create a free project at supabase.com
2. Open the SQL editor and run `schema.sql`, then `seed.sql` (in that order)
3. Go to Authentication → Users and manually create two users matching the seed data:
   - `ahmed.manager@demo.com` (any password) — copy the generated UUID
   - `rahul.rep@demo.com` (any password) — copy the generated UUID
4. Update the `users` table rows in `seed.sql` (or via table editor) so their `id` matches
   the actual Supabase Auth UUIDs generated above — Supabase Auth's user id must match
   your `users.id` for the app's role lookups to work.
5. In seed.sql, update customer `latitude`/`longitude` to somewhere near where you'll
   actually demo from, so geo-fenced check-in succeeds live.
6. Upload 3 sample PDFs to Supabase Storage (bucket: `documents`, make it public) and
   update the `file_url` values in the `documents` table to match.

## 2. Set up email (Resend)
1. Create a free account at resend.com, get an API key
2. For a real demo, verify a sending domain (or use their sandbox `onboarding@resend.dev`
   which only sends to your own verified email while unverified)

## 3. Environment variables
Copy `.env.local.example` to `.env.local` and fill in:
```
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
RESEND_API_KEY=
```

## 4. Run locally
```bash
npm install
npm run dev
```
Visit http://localhost:3000 → redirects to /login.

## 5. Deploy
Push to GitHub, import into Vercel, add the same env vars in Vercel's project settings.

## Demo script (suggested order)
1. Log in as rep → Home (shows follow-ups + at-risk customer alert)
2. Customers → open Al Noor Trading → shows 360° view + declining pricing
3. Visit → Check In (geo-fence verifies location) → close visit with notes/next action
4. New Order → select Al Noor Trading → note price differs from other customers →
   try adding the out-of-stock item → shows alternative → add cocoa → see cross-sell
   suggestion appear → Request Special Price on a line → Submit Order → watch the
   status pipeline animate through to "Confirmed by Sage X3" with an order number
5. Documents → send the cocoa spec sheet to a customer by email → check inbox live
6. Alerts → show the purchase decline flag on Al Noor Trading
7. Log out, log in as manager → Dashboard (charts) → Approvals (approve the discount
   request from step 4 — the rep's app updates in real time via Supabase Realtime) →
   Team (rep activity summary)

## What's simulated vs real
- **Real**: auth, role-based routing, all data (Supabase), email sending (Resend),
  geo-fence check via device GPS, realtime approval sync
- **Simulated**: the Sage X3 order sync (no ERP sandbox access) — the status pipeline
  and order number are generated by `/api/orders/[id]/advance`. Swap that route's logic
  for a real Sage X3 Web Services / OData call once ERP credentials are available.
- **Not built** (mention in proposal only): WhatsApp document sharing (would use Meta
  Cloud API or a BSP like Twilio/Gupshup), voice-to-text (Web Speech API stubbed as a
  button on the visit form, not wired up)
